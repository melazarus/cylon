Firmware update

Flashes the board over USB through the ROM bootloader. WebUSB needs a Chromium browser (Chrome or Edge, desktop or Android) and, on Windows, the WinUSB driver for the bootloader. 


  


  

    

      Setup notes & troubleshooting
      
    
        
  • Web MIDI (LEDs, animations, pins) works in Chrome, Edge and other Chromium browsers over HTTPS. iOS Safari and Firefox are not supported.
    • 
        
  • Windows flashing: install the WinUSB driver for the WCH ISP device with Zadig (select the device, choose WinUSB).
    • 
        
  • Linux flashing: grant access to the bootloader with a udev rule (it may be either VID), then reload and replug:
          
    SUBSYSTEM=="usb", ATTR{idVendor}=="4348", ATTR{idProduct}=="55e0", MODE="0666"
          
    SUBSYSTEM=="usb", ATTR{idVendor}=="1a86", ATTR{idProduct}=="55e0", MODE="0666"
          
    sudo udevadm control --reload-rules && sudo udevadm trigger
          
    If the device shows up but flashing says Access denied, the rule is not in effect yet. Check ls -l /dev/bus/usb/<bus>/<dev> shows crw-rw-rw-. Snap/Flatpak browsers are sandboxed and need extra USB permissions.
    • 
        
  • Stuck after flashing? Unplug the board, hold the BOOT button, plug it back in, then connect and flash again.
    • 
        
  • No device in the picker? On Windows the bootloader usually needs the WinUSB driver (Zadig). On Linux the udev rule above is required. Make sure no other tool (WCHISPStudio, pio upload, a serial monitor) has the bootloader open. If it still doesn't show, tick Show all USB devices — the log prints the VID/PID of whatever you pick.
